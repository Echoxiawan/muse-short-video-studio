# 交付说明模板

按 [references/qa-checklist.md](../references/qa-checklist.md) 检查后再填。没查过的项写「未查」，不要写成通过。

```markdown
# Delivery notes — [项目名]

- 日期：
- 模式：A / B / C / D（可写「先 A 后 B」）
- 画幅：
- 语言：
- 成片路径（ASCII）：
- 分段文件（如有）：
- 总时长 / 场次结构：

## 使用与吃进情况

- 提示词或策划版本：
- 吃进项：
- 偏差项：
- 原因推测（标明这是推测）：

## 连续性

- 采用方法：模式 B 快照顺序接续 / 模式 C 同一文件 Match Cut / 未采用（单段或无人物连续）
- 快照 id 或共享关键帧文件：
- 交界检查结果：

## 音频（待用户终验）

- 原片是否已有音轨（ffprobe 结果）：
- 对白 / 旁白策略：
- 需要用户亲自听或看的部分：语言与口音、口型、环境声、配乐、音量

## 执行信息（仅模式 D 或实际调用了生成后端时）

- 用户已确认的后端：
- 任务 id / 资产编号（仅供续做，不当外链）：
- 是否只提交了一次；如有经同意的重提，原因：
- 额度变化与重置时间（如能读到）：
- 不要在此处粘贴密钥或令牌

## 结论

- 判断：可交付 / 后期可修 / 重跑某段 / 不通过 / 仅完成策划
- 若重跑：哪一段时间、用哪一种连续性方法
- 下一步建议：
```

---
改编说明：交付必须包含抽帧结论与「待用户终验」项，改编自 Mason Mosen 的产出约定（MIT）。
