# 模式 D：执行后端（默认关闭）

本模式默认不启用。只有用户明确同意某个执行通道后才能调用。本包不附带第三方付费客户端，也不把任何代理 API、工作流平台或内部命令路径当作依赖；未同意之前，把提示词和策划交付给用户，请他们在已授权的界面里生成。

## 启用前必须说清并得到同意

按用户实际要走的通道，用对方听得懂的话说明这些点，得到明确同意后再执行：

- 将要使用哪一个后端（当前环境已登录的官方生成能力、用户已经在用并确认过的第三方代理、或仅提供提示词由用户自己点生成）。
- 若通道是第三方代理：说明它与模型提供方无隶属关系（如适用）、需要哪些令牌或账号、是否另有订阅费、会不会消耗原服务的额度或周限额。
- 令牌和密钥只进入环境变量或密钥库，绝不能出现在聊天、日志或本仓库文件里。
- 预估会跑多少张图、多少段约 10 秒的视频，以及可能消耗的额度。多于两三条视频，先报告再开工。

用户拒绝或没有指定后端：停止在策划与提示词，不要自行开通服务。

## 执行纪律

1. **先查额度再开工。** 能读到计划、已用比例和重置时间就写进开工说明。额度不足时不要提交可能扣费的任务。
2. **可能扣费的生成任务只提交一次。** 失败或中断后禁止盲目重提。用任务 id 恢复等待和下载。上传、查询、下载是否消耗生成额度，以当时接口为准；在确认「这次调用不会再扣一次」之前，不要把查询当成可以随便重试的生成。
3. **超时要分情况。** 若接口表示任务可能已经做成但结果尚未取回：先用任务 id 查询，问用户后再决定要不要重提。若接口明确表示尚未开始渲染、可以确认没有产物，才在征得同意后重试。
4. **用资产编号把结果送进下一任务**，不必把同一文件重复上传。不要把资产编号当成可对外分享的成片链接。同一任务的全部输入应属于同一账号（若后端区分多账号）。
5. **把精确画幅写进提示词。** 许多接口没有独立的比例、分辨率或时长参数。使用 `in exactly 16:9 aspect ratio` 这类直接约束。接口不支持的更短时长或更高分辨率，不要假装会生效。视频仍按约 10 秒规划。
6. **在提示词里点名实际传入的输入**（如「image_1 中的人物骑着 image_2 中的车，经过 image_3 的海滩」）。点了名却没传对应输入，或传了未提及的输入，都容易被拒绝。
7. **写明必须保持不变的部分**：脸、构图、裁切、物体位置、是否允许镜像重画。
8. **内容拒绝、安全验证、额度用尽、限流时停止并报告。** 不要用同一提示词反复硬碰。被内容策略拒绝后应改写或更换输入，而不是原样重提。限流则等待后再问用户是否继续，不要写死循环。
9. **不要把表格批量、工作流批量或某条内部命令写成默认能力。**
10. **人脸、旧照、换人**先确认已有权利人授权，不用于误导或未经同意的身份冒用。

## 常见任务怎么写（仍须先有已确认的后端）

以下是提示词与步骤上的纪律，不是某个客户端的用法说明。字段名按你实际后端的输入槽位改写。

### 文生图

在提示词开头写死画幅，描述主体、光线、材质和限制。需要多图合成时，点名每一张输入图贡献什么，并写清「哪一部分必须保持原样」。

### 改图 / 多图合成

说明要改什么、要保留什么。合成时分别绑定「人物来自哪张图、场景来自哪张图、道具来自哪张图」，避免模型自行重画整张图。

### 旧照修复与上色

列出要处理的问题（划痕、褪色、污渍、颗粒、上色），并强调保持与原图相同的构图、裁切和画幅，不要重新构图或年轻化成另一张脸。交付时说明这是修复方向，不是身份鉴定。

### 照片说话（图生视频）

先上传或引用那张已授权的照片，再写：在相同构图下让人物做哪些动作、说哪一两句短台词（引号标出，注明语气）。要求面部与照片一致，但不要承诺锁脸一定成功。单段仍按约 10 秒规划。

### 视频换人

写清「替换 video_1 中的某个人为 image_1 中的人，其余画面尽量保持不变」，并处理对白是否更换。先确认两段素材的授权。换人不是模式 C 的角色锁定方案，也不要用它来接有连续角色的剧情长链。

### 无脸旁白短片的有限并行

没有需要认脸的角色、只靠旁白和景物推进时，可以有限并行（例如一个主题最多三场再拼接），并可用同一条固定音频铺到各镜，避免音色漂移。这种方法**不用于**需要人物连续的动画或剧情片。

## 建议的执行顺序

```
确认后端与费用
  → 查询额度
  → 用户定稿提示词（原文提交，不擅自扩写）
  → 如需用户文件：上传一次，记下资产编号（文件名 ASCII）
  → 提交一次生成，保存任务 id
  → 等待或中断后用任务 id 恢复
  → 下载到本地（ASCII 文件名）
  → 需要续做时用资产编号链接下一任务
  → 按 qa-checklist.md 抽帧或目视检查后交付
```

多段连续人物的电影感短片仍应回到模式 B 的快照顺序接续；有角色表和首尾帧的动画短片仍应回到模式 C 的 Match Cut。模式 D 只解决「在已确认的通道上怎么安全地执行」，不取代前两种连续性方法。

## 交付时要写的执行信息

- 使用了哪一个用户已确认的后端（不要回显密钥）
- 任务 id、资产编号（仅供继续作业，不当作对外链接）
- 提交次数（应当是一次；若用户同意后的必要重提，写明原因）
- 额度在执行前后的变化（如能读到）以及重置时间
- 接口返回的说明原文（如有）
- 待用户终验的音频、口型、身份相似性
